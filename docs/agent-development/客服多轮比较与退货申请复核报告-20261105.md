## 截图问题及修复

1. “比较第一个和第二个”返回一个商品：数量提取把“第一个”误识别为只要一款；比较节点也未按序号选取原列表。现在独立提取comparisonPositions，比较只接受上一轮2—3个有效对象，按原序重新查询详情。比较结果使用价格、同SKU库存、属性、在售状态对照表；保留原3款记忆，连续比较第一/第三不会丢失第三款。缺失记忆或越界时澄清，不随意选择。
2. “退一下订单的货”返回“未发现异常”：原先只走异常诊断，未识别操作诉求。现在在已核实本人订单的前提下优先展示办理步骤、待核验条件和生成方案入口。没有异常不等于不允许申请；也不等于自动获准退款。退货诉求服务端强制高风险，用户确认后进入管理员审核。
3. 申请按钮隐藏：统一结果增加canCreateCase/showCaseProgress；前端不再必须先点完整证据才能生成方案。Java仅从本人已保存诊断创建方案，不信任客户端伪造的订单事实。用户需核对方案、输入原因并单独确认；不自动提交。
4. “查询我的售后申请”与政策咨询混淆：复用现有本人案件列表接口，独立识别进度查询；“如何换货，请查询政策，不要提交申请”不进入申请或进度流程。
5. 复合任务中政策长文淹没导购结果：顶部先标明两个分支的实际结果；无匹配商品明确品类、预算与未命中情况，不伪称两个业务均成功。精简政策节选中重复条号，完整原文、来源、版本和证据仍保留。
6. 20元内茶杯：本机在售商品名称“茶杯”查询为0，实际LangGraph工具搜索也无结果。不会拿饮水杯或其他商品冒充；如需新增茶杯须另行提供并确认商品资料。
