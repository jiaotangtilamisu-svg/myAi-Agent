# 第31阶段审计与分批计划

基于第30阶段现有隔离数据层、来源映射、只读供应商契约及REAL推荐门槛继续实施。现有12商品/13SKU/12库存/4订单为演示数据；两政策草稿未审核，正式778号61向量。以上基线将以本轮快照复核。保留全部未提交修改，不重写Agent。

1. 核验许可与下载方式。优先研究Amazon2023，但不下载类别完整大文件；其商品价格币种及演示使用权未确认前不用。尝试CC0 Wikidata的手机/耳机型号资料，100～130条、最多两类、评论0条，无图片，单响应硬上限1MiB、下载总预算远低于100MB。型号资料不当零售报价，没有价格/库存就保持null。
2. 先备份业务库和现有simlect_data_governance，再复用etl_batch/source_record/historical_record事务写入与幂等；不向原商品/订单/库存表写入。通过批次状态可逆停用进行回滚，不删除旧记录。
3. 在既有Product微服务增加只读公开资料查询与既有Admin权限下批次查询；前端明确标注公开资料、非当前可购买、历史/未知价格、未知库存和来源时间。不是独立替代商城，不让REAL推荐使用这些资料。
4. 复核官方原文、草稿及原有61向量；补充必要的法规审核材料但不重复导入、不自动发布/向量化。政策缓存每次仍经正式目录校验。
5. 增补HTTP429/500等Mock稳定性测试，保留DeepSeek/text-embedding-v4配置、20秒/0重试/512政策Token及完整证据。新付费调用先报告预算，等待批准。
6. 专项→受影响模块→可执行回归；真实浏览器优先采用现有能力，无法可靠识别URL或需要登录时停止该环节，不读取凭据，不以HTTP200替代UI通过。

本阶段正式商业源仍不存在；公开资料只供展示/搜索/算法测试，不生成SKU和库存、不启用购买。需用户单独批准：真实API费用、政策审核发布或破坏性迁移。若小样本抓取失败/不足100条，保留失败证据并换合法小样本，不扩容下载。
