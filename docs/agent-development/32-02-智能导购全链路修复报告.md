# 第32阶段智能导购全链路修复

## 结构和修改

继续使用shopping/extraction.py→requirements.py标准对象→LangGraph understand/search/details/select/compose→SEARCH_PRODUCTS/GET_PRODUCT_DETAIL→Java Product/Stock。没有重写Agent或替换DeepSeek。模型只补充有原文依据的槽位；不能扩大已确认的硬品牌集合。规则解析是受校验的降级路径，本轮没有调用模型。

requirements.py统一三星/Samsung、苹果/Apple/iPhone、华为/Huawei、小米/Xiaomi、荣耀/Honor、OPPO、vivo；添加台灯品类、价格往上/至少/最多花/预算提高到、品牌排除和数量追问。近似“8000左右”保存budgetTarget并澄清范围，不私设误差。currency=CNY；fieldEvidence保留本轮原文或可信会话来源，RULE_VALIDATED不是统计置信度。软性品牌和512GB偏好不能抹除硬性条件。

selection.py继续在同一SKU校验价格、规格和库存；保留原reason并增加failureReasons。explanations.py根据真实排除原因解释品牌/品类/价格/规格/零库存/未知/服务异常。graph.py保留requirementEvidence和retrieval诊断。没有为了凑三款放宽条件，没有把未知价格库存改为0。

runner.py持久化完整fullReport；公开商品来源和本地配置字段在卡片中明确区分。MCP返回普通文本、错误文本、旧协议都不能成为已核实商品。product_service.py/retriever.py借助任务局部retrieval_trace保留关键词、向量、降级状态，避免并发串扰。
