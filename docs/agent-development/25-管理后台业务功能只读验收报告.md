## 4. 库存语义与一致性

- 库存表仅有`product_id`、`property_value_id_hash`、`stock`三列。`stock`被现有业务代码用作可售库存；不存在单独的物理库存、锁定库存、冻结库存列，不能把这些字段说成已支持或默认0。
- SKU库存记录12条，孤立库存记录0条；13个SKU中1个缺库存记录：`V16142348S / a5e6820334bac21b9dbf24b1171398d2`。
- `V16142348M`两个SKU库存分别7与0，0是存在记录的真实零值；`V16142348S`为没有记录的未知值，不等价。
- Product管理详情`ProductInfoServiceImpl.getProduct4VOByProductId`逐SKU调用`StockFeignSupport.getAvailable`。`SkuStockService.getStock`找不到记录返回0；Support也将空对象/空stock变为0。**这条普通管理链路不能可靠区分缺记录与零库存**。
- 增强Agent链路`ProductAgentQueryService.queryBatch`→Stock `queryBatch`根据缺失记录输出`stock=null`、`stockQueryStatus=MISSING`、`availability=UNKNOWN`，与普通管理详情语义不同。此为源码确定的分歧，本轮未修改。
- 管理列表`findListByPage4ListVO`按商品求库存总和；缺失库存行不会被计入，可能掩盖不完整性。当前管理页面中并没有独立的锁定库存展示。
- **运行态Stock查询与管理详情逐SKU对比尚未通过验收**：不读取内部Token、不绕过认证；本轮没有采用匿名直连受保护接口替代业务会话。
