## 业务关系与库存含义

- product_info.product_id → product_sku/product_property_value.product_id。SKU唯一键为(product_id,property_value_id_hash)，hash来自管理端规格值ID组合的MD5，非商品真实品牌或供应商编码。
- sku_stock位于simlect_stock，唯一键同上；stock是现有扣减后的可售余额，没有独立reserved字段。预占复用changeBatch负数变更，释放使用正数并传requiredOperationId，不能再减一次“预占量”。
- order_info.order_id → order_item.order_id；order_info.user_id归属user_info.user_id。内部Token与业务用户校验分开，订单明细通过所属订单校验。
- 订单状态复用OrderStatusEnum：-1删除、0待付款、1已付款待发货、2已发货、3完成、4取消、5关闭、6退款关闭、7部分退款、8待评价。历史Olist状态不直接转换成这些当前业务状态。
- Product事务/Outbox通过RAG_EXCHANGE、RAG_QUEUE_KEY发送PRODUCT事件；Search RabbitMQRagListener消费并更新ES向量。新增关键词同步补丁见实施/测试报告。索引simlect-index、simlect_vectorstore均保留。
- 既有导入/写入：管理员/admin/productInfo/addProduct、updateProduct、addBatch；Stock/internal/stock/changeBatch；订单/api/order/postOrder。不得用addBatch直接绕过SKU、库存、来源和事务校验。
