### 高概率原因（推断）

更符合现有证据的是：三个依赖控制台的服务启动链在相近时刻受到外部控制台/宿主层面的终止或中断，而非三个业务应用各自独立崩溃。依据为近乎同时、同退出码、监督父进程也消失、没有应用致命堆栈、Product/Gateway 继续运行。

这是原因类别判断，不足以进一步区分键盘信号、关闭某个或多个控制台、终端管理操作、外部任务宿主清理或其他能够产生同类退出状态的行为。

### 尚无法确认

具体信号类型与发送者、是否存在共同控制台/进程组、是否受外部 Job Object 管理、监督 PowerShell 的精确退出时间/退出码、MCP/Agent 实际服务子进程的精确退出信息，以及事件与 Product 启动之间是否存在因果关系。

## 7. 脚本与控制台生命周期分析

只读审阅文件：`scripts/local/start-order.ps1`、`start-mcp.ps1`、`start-agent.ps1`、`service-common.ps1`、`ServiceLog.cs`、`deploy/run-configured.ps1`、`deploy/start-local.ps1`。

- 三个独立服务脚本调用 Invoke-IndependentService；ProcessStartInfo 使用 UseShellExecute=false、CreateNoWindow=false、stdout/stderr 重定向，启动后 WaitForExit。它是前台监督器，不是 Windows Service。
- CreateNoWindow=false 和隐藏窗口不能保证独立控制台或免疫控制信号；当前已经退出，未在故障前采集控制台附着进程列表，因此无法确认当时是否共享控制台。
- ServiceLog.cs 的 Dispose 在子进程仍运行时直接返回，不调用 Kill；退出回调只写 exit.json。代码未找到进程清理、自动重启、AssignProcessToJobObject 或信号广播。
- Product/Gateway 的 Start-LocalProcess 使用 Start-Process -WindowStyle Hidden -PassThru 及独立输出文件；没有 -Wait，外层等待端口后退出。Product 的 -Stage Java -Service product 会过滤其他服务，未见停止其他服务的分支。
- 这些脚本没有显式 Job Object 绑定，但不能由此否定操作系统或外部宿主曾施加 Job；进程已经消失，当前无法回溯其 Job 成员关系。
- 原独立脚本明确要求控制台保持打开；曾通过跨 Codex 任务观察，只证明那段时间存活，不能视作抵抗任意控制台关闭事件的永久保证。
