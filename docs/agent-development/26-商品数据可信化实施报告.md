## 核心变更及数据契约

1. Admin商品列表、详情和编辑入口先清洗封面字符串；空封面/坏图片使用本地SVG占位图。预览无SKU或空封面时不再调用undefined.split；切换商品清理旧选择，零库存SKU仍可查看。
2. Admin Price统一使用displayAmount，null、空值、非有限及负价格显示未知，真实0显示0.00。SKU重建保留null、stockQueryStatus和同一SKU标识，不借用其他SKU的价格，不再自动给新组合填0库存/0价格。
3. Product管理列表与普通商品详情复用现有ProductAgentQueryService聚合及Stock queryBatch，不逐SKU发库存请求。列表按50商品分批；SKU库存仍由Stock服务提供，未在Python重建库存业务。
4. Stock getStock缺记录返回stock=null；普通库存Support对未知抛出明确业务异常，不能默认为0。管理详情SKU返回stockQueryStatus=SUCCESS/MISSING/UNAVAILABLE/INVALID_RESPONSE等。价格字段保持null，另有priceStatus=KNOWN/UNKNOWN。Product汇总库存只在全部SKU已知时返回数值。
5. MySQL显式按价格排序时增加knownPriceOnly，排除min/max未知的商品；Search ES价格排序增加价格存在条件。原有ES检索、Java回源与MCP保持不变。
6. 导购仍以同一SKU事实作预算判断；未知SKU价格既不满足预算，也不参与“便宜”筛选。未知库存保留警告而非现货承诺；历史/合成来源的既有隔离规则保留。
7. 商城详情与SKU弹层、商品卡片、收藏/足迹价格展示使用可空可信值；已选择SKU价格未知时禁止回退为商品最低价。详情结算和SKU加入购物车的客户端校验阻止未知价格、未知/零库存；购物车未知价格不参与可结算选择，展示未知，不把它们相加为0。仅修改校验代码，未实际加入购物车或下单。

示例契约：`{price:null,priceStatus:"UNKNOWN",stock:null,stockQueryStatus:"MISSING"}`，与`{price:0,priceStatus:"KNOWN",stock:0,stockQueryStatus:"SUCCESS"}`严格区分。技术数据源仍为product_info/product_sku与Stock sku_stock；未自动把UNRECORDED或演示数据升级为LIVE_API真实商业来源。
