## 规则与数据契约

understand保留原多轮条件，支持人民币/元/块/块钱，预算、最多、不超过、不到、控制在、以内/以下及中文金额。不到20采用严格小于20；20个/二十个不会当作金额。覆盖用户给出的全部20/3000预算表达，另有中文数字和多轮回归。LLM仅补充有用户原文依据的要求，不是价格/库存事实来源。

茶杯（含喝茶的杯子）、保温杯、水杯（含运动水壶）、手机/智能手机、耳机/蓝牙耳机、键盘/机械键盘、笔记本电脑分别处理。按Java实际商品名和分类验证，不用宽泛数码/杯字匹配，也不生成分类ID；手机壳等不能替代手机。

select逐SKU应用预算、属性与可售库存条件。已下架及确定零库存排除；价格未知不符合预算；库存服务失败保留null与失败状态，库存未知只作为待确认。最多3款，评分只为可核实事实及明确条件匹配分。

数据字段继续使用schemaVersion=2商品工具契约：product_id/product_name/product_status、skus[].sku_id/sku_name/price/stock/stock_query_status、query_time、data_provenance。推荐卡片补充recommendationReasons、productObservedAt、dataClass，兼容旧卡片。未新增业务接口或数据库表。

当前设置默认DEMO，答复明确说明演示环境。DEMO前缀记录标为DEMO，合成字段标TEST；缺来源/只有手工资料标UNKNOWN。REAL必须有LIVE_API来源名称，且price、sku、stock关键字段均为LIVE_API。用户明确要求真实商品时也会收紧条件；模型不能把来源模式降级。现有12个商品仍属于演示/验收目录，不能因此宣称已有企业真实商品。
