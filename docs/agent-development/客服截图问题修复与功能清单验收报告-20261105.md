## 六张问题图的处理

1. **手机误推荐行车记录仪**：商品名称提及“手机”不再直接证明它是手机。Python按Java品类、主营商品及配件排除规则筛选；Java普通搜索与MySQL回源排除记录仪、摄像监控、打印机、题库、会员等误命中。扩大有限候选窗口至50，先按预算和品类预筛，再截取最多12件详情批次，最终重新验证SKU价格库存。
2. **推荐三个手机**：继续解析目标数量、清理新请求不应继承的旧预算；不足时不编造。运行查询已返回3款真正的手机。
3. **退货操作问题被当成“有没有异常”**：保留诊断事实，另加办理指引；说明订单页可用入口、未发货与已发货的区别、需要人工核验、未经确认不自行寄回。未发现订单异常不等于不允许申请售后。本次没有代用户提交申请。
4. **笼统查政策只有LOW_RELEVANCE**：新增显式、只读的政策概览词项浏览，不假装它是高向量相似度；不调用Embedding。仍验证已发布目录、有效期、版本、Chunk及正文哈希。
5. **换货查询不可用、内部码外露**：换货主题可以走经验证的条款词项检索，来源与原文保留；政策状态显示为中文。原语义检索的阈值及Embedding失败分类保持不变，没有靠降低阈值放入低相关度证据。
6. **本人订单列表误要求订单号**：Supervisor独立处理列表，只用可信当前登录身份调用QUERY_ORDERS，返回真实列表；单笔诊断才要求订单号。独立售后模式亦优先显示已查询的本人订单候选列表。

## 新增申请和履约界面

- 消费端：聊天中新增售后方案、单独确认提交、本人申请进度、驳回后补充重新提交。统一助手可先打开完整依据，再对有本人订单事实的诊断生成方案。
- 管理端：既有售后案件详情增加退货类型、物流公司、运单、验收结果和本地模拟退款入口。
- 模拟开关：`simlect.aftersales.mock-refund-enabled`默认false，不接受请求体或模型覆盖。本次没有修改环境配置开启它。
- 新操作必须案件IN_PROGRESS、管理员且当前任务处理人；版本和幂等检查继续适用。办理类型不能中途切换绕过验收，已验收物流不能覆盖；模拟退款不接真实支付接口，用户提供的退款ID和执行标志不能覆盖服务端生成值。
- 模拟成功仍不是银行到账；案件最终处理和归档继续由人工记录。
