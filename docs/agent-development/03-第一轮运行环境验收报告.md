## 8. 首次失败与环境问题（均保留原始证据）

1. 首次 Maven 命令的 PowerShell 参数引用不正确，`.failIfNoSpecifiedTests=false` 被识别为生命周期阶段，0.717 秒退出；此时没有编译或服务重启。只改了工具命令的引号，后续构建和 166 项回归成功，未修改 POM/源码。
2. 独立 Java 夹具首次将主类和网络保护类同时置于 bootstrap classpath，导致 ObjectMapper 不可见；之后又遇到 Windows NIO 在长临时目录下回退 TCP 与网络保护冲突。仅调整临时夹具的类路径和原项目已使用的短临时目录；没有改正常服务或业务代码。
3. 首次运行验收记录 30 项：29 通过、1 失败，另外四项依赖有效提案的确认检查没有执行。失败项是隔离 MCP 退款建议，根因是 HTTPX 使用系统代理 7897 访问本机 Mock Java，被隔离网络保护正确拦截。诊断确认显式直连本机成功，默认客户端却选择代理。
4. 为隔离 MCP/驱动设置仅本机 NO_PROXY 后，只重启该隔离 MCP 并复测隔离部分；24 项通过。正常实例的 10 项首次已通过，未为了复测覆盖其 Redis 会话。最终取隔离复测 24 项 + 正常实例 10 项，形成 34 项完整清单，不累计重复执行。
5. 首版验收驱动即使记录了失败也未设置失败退出码；报告没有使用退出码伪装全部通过，而是保留逐项 JSON。后续临时驱动修正了失败退出码，隔离复测退出码 0，逐项断言也全部通过。

以上问题均属于本轮测试工具/执行环境，未发现需要修改业务源码的运行异常。正常进程还出现过低于 4 GiB 空闲内存的启动提示，但最终健康通过，未重启其他程序释放内存。
