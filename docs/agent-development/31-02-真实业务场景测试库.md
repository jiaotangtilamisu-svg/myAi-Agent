# 真实业务场景测试库

日期：2026-11-05（Asia/Shanghai）。所有结果来自本轮实际执行。真实LLM、Embedding、支付、退款及下单调用均为0；未提交Git，正式业务数据只读。

## 可复用交付

- tools/quality_engineering/scenarios.json：67条预算/品类语料+5条独立路由预期；为可审阅静态预期，不由生产解析器生成答案。
- fixtures.py：直接构造小型原始业务协议Fixture，不借助Agent规范化函数生成预期。
- oracles.py：独立于Agent实现，直接使用原始Fixture验证预算、完整候选准入、同SKU报价/库存、来源、政策原文/发布状态、调度不重复。
- Agent tests/test_quality_properties.py、test_quality_fault_injection.py：本轮新增共144个pytest用例（含参数化），已纳入完整911项，不额外相加。
- Java AftersalesCasePersistenceTest：新增8个参数状态测试，每个执行9类命令，共72个状态-命令组合；另补空方案、失败参数类型、运单验证。订单与案件使用实际Mapper/事务+新内存H2，外部订单Fixture明确Mock。
- 前端trustedProduct.test.ts：拒绝数组、对象、日期、十六进制等被JavaScript隐式转成价格；管理端验证无实际字符的运单不能通过。

## 场景维度

导购：手机/耳机/茶杯/杯子、预算0/1/20/199/200/300/3000、1k/三千、全角数字、两种20以内表达、价格区间、材质/尺寸/颜色、品牌硬约束与优先偏好、未知/零库存、未知价格、来源不可信、SKU身份缺失/重复、多轮条件恢复失败、否定品类、耳几/手几常见错字、2至3比较。

售后与政策：本人/他人订单、明细与物流、无订单/无政策/低相关/冲突证据、七日与质量分开、退款不自动执行、确认取消/重放、原因材料、管理员审批、用户运单、物流异常、验收成功/失败、模拟失败/成功、固定退款单号、非法状态不写审计。

Supervisor：单任务/复合/模糊、重复Agent禁止、超时/失败、部分结果保留、不同用户及专业上下文隔离，三种原模式不删除。

前端：消息/历史/恢复/证据、未知价格/库存、权限错误、取消确认、并发状态、原始审计JSON消费者显示；浏览器实际点击与Node工具测试分开。

## 属性/随机测试

种子3101/3102固定：160轮五商品预算/库存网格、80轮双SKU上下架/库存失败网格、150轮Unicode/非法字符随机文本，共390轮循环，生成960个SKU配置。循环次数不是pytest用例数，不能加到测试总数。全部仅内存Fixture，不写业务库。

等价类、边界、否定、组合、可重放Fuzz、候选准入单调性及完整性均有程序断言。只对完整候选集检查放宽预算后的准入单调性，不错误要求前三名排名永远不变。

## 本机读取与隔离区别

本机推荐/比较和法规读取使用真实MCP、Gateway、Product、Stock、Search/ES；不会用Fixture冒充真实目录。Supervisor混合集成明确将LLM与状态通知隔离，专业图及商品/政策读取是真实服务。订单和资金写状态仅H2/Mock，不能当真实交易验收。

新增隔离HTTP闭环同时运行真实Controller、AuthCookieHelper、CaseAuthentication、Service、Mapper与H2事务；Redis登录记录和外部订单查询为Fixture。涵盖11条审计事件及失败重试同单号，不是正式业务库或浏览器验收。
